## Limitações conhecidas

- Idempotência do webhook genérico depende do caller enviar `eventId`; sem ele, o path antigo (sem dedupe) é usado. O path Stripe assinado já era idempotente por conta própria.
- Os 3 jobs compartilham um único `intervalMs`/`batchSize` do retry worker — sem cadência independente.
- ⚠️ **Latente:** `tenant_usage.storage_bytes` é `integer` (máx ~2,1 GB). Planos com storage em GB vão estourar o tipo. Precisa migrar a coluna para `bigint` (migration futura) — não corrigido aqui para não misturar escopo.
- ~~Reconciliação só on-demand~~ — **fechado**: worker de cadência lenta (24h) `usage-reconcile.worker.ts` reconcilia todos os tenants; endpoint on-demand continua disponível.
- Notificação de trial expirado é **best-effort** (try/catch silencioso); falha de email não reverte a transição de status nem reagenda envio dedicado (depende da fila de email existente só em caso de falha de envio direto).

- Teste `billing-status-gate.spec.ts`: past_due → 402; active → 201; past_due ainda lê dados (GET 200).
